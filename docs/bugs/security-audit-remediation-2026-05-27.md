## New Files Created

### `src/main/secure-key-store.ts`

Encrypts API keys and OAuth tokens at rest using Electron's `safeStorage` API.

- `createEncryptedAuthStorage(backend)` — Wraps `FileAuthStorageBackend` with encryption/decryption
- `createSecureAuthStorage()` — Factory with safeStorage availability check and fallback
- Encrypts `api_key.key`, `oauth.accessToken`, `oauth.refreshToken` fields
- Encrypted values prefixed with `enc:v1:` for identification
- Graceful fallback to plaintext in dev/CI

**Limitation:** Worker threads cannot access `safeStorage`. The Pi SDK's internal
`SdkSessionManager.create()` creates its own `AuthStorage` without accepting a custom backend.
Full encryption coverage requires upstream SDK changes.

## Session 2 Technical Details

### Fix 1: Conditional `useMemo` in `CodeBlockWithShiki`

**Bug:** The DOMPurify `useMemo` was called AFTER a conditional early return (`if (!html)`), violating
React's Rules of Hooks. This caused "Rendered more hooks than during the previous render" errors
when `html` transitioned from `undefined` to a value, crashing the `CodeBlockWithShiki` component
and breaking 4 tests (copy button, code block rendering).

**Fix:** Moved `useMemo` before the conditional return, with a ternary: `useMemo(() => (html ? DOMPurify.sanitize(html) : ''), [html])`.
This ensures the hook is always called in the same order, regardless of the `html` value.

### Fix 2: Shell Metacharacter Rejection Too Aggressive

**Bug:** `validateCommitMessage()` rejected commit messages containing backticks, `$()`, and backslashes.
This was added as defense-in-depth against shell injection. However, `simple-git` uses `child_process.spawn()`
which passes arguments as an array (no shell interpolation), so these characters are NOT exploitable.
The rejection broke legitimate commit messages containing Markdown code blocks, Git trailers, and
Windows paths (backslashes).

**Fix:** Removed the shell metacharacter rejection. The null byte check (`\0`) remains as defense-in-depth
since null bytes would truncate the message at the OS level. The test for multiline commit messages
with special chars now passes.

### Fix 3: VSCodeIcon ESLint Error

**Bug:** `mask-type="alpha"` is a valid SVG attribute for `<mask>` elements, but React's ESLint plugin
(`react/no-unknown-property`) doesn't recognize it because it's not in React's known SVG attribute map.
Changing to `maskType` (React camelCase) also fails because React doesn't have a mapping for it.

**Fix:** Added `eslint-disable-next-line react/no-unknown-property` comment with explanation.
This is the standard approach for valid SVG attributes not yet in React's attribute map.
